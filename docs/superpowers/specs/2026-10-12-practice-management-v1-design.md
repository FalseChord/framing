# 診所營運管理平台 — 設計文件（V1：心理師資料庫 + 個案資料庫 + 值班儀表板）

## 背景與目標

這是「framing」專案四個子系統中第二～四個子系統的合併規劃，見專案總覽的分解順序：

1. 信件模板系統（已完成）
2. 心理師資料庫
3. 個案資料庫
4. 櫃檯值班儀表板

**本次規劃的決定性變化**：原規劃是分階段、由簡入繁逐步做（行政先上線，心理師自助後補）。經過一輪角色發散（管理者/個案/行政/心理師/法規五個視角）與需求盤點後，確定 V1 一次把心理師自助功能（登入、個人視圖、諮商紀錄輸入、抽成查詢）也納入，不分期。這個決定直接推翻了信件模板系統時期「無密碼單機」的身份設計前提——心理師需要跨裝置、只能看自己資料，必須有真正的身份驗證與角色權限，详見下方「架構決策」。

子系統 1（信件模板）在本次規劃中被歸類為「值班儀表板」底下的既有功能，整合方式見「功能範圍」第 8 項，不重做。

## 功能範圍

### 涵蓋（V1）

**行政核心**
1. 方案設定：方案名稱、預設收費、時長、抽成規則（可被心理師個別收費覆寫、可被個案類型覆寫），支援固定堂費/固定比例/階梯級距三種抽成公式並存；方案可停用（沿用心理師停用的軟刪除模式）
2. 個案資料庫：建檔、三段式狀態（待排→治療中→已結案）、搜尋/篩選
3. 進案建檔：系統內建原生表單（取代目前的 Google 表單），依方案顯示對應欄位，個案自填 + 行政一鍵審核
4. 排程管理：單次與週期性排程，雙重衝突檢核（心理師可服務時段 + 場地資源）
5. 出席登記：已到/未到/請假/改期，心理師與行政共用同一套狀態資料，差異只在誰能觸發「改期」這個入口；改期動作會建立新排程記錄並連結回原時段，保留異動歷程
6. 費用與收款：正式連號收據（作廢/修改留痕）、多種收款方式記錄、支援部分收款與退款（以負向調整項處理）、收據可自動寄送個案信箱
7. 值班儀表板：今日場次總覽、待辦提醒（提醒規則彈性程度為待確認事項，見下方）、採定期輪詢更新畫面（非即時 WebSocket）
8. 信件模板整合：從個案/排程資料一鍵帶入既有信件模板系統，取代手動輸入個案姓名等欄位；信件生成與個案狀態保持獨立，不互相連動
9. 心理師資料管理（行政端擴充）：可服務時段（每週重複樣板）、擅長方案（限定從方案清單勾選，非自由文字）、預設抽成比例

**心理師自助**
10. 心理師登入：密碼驗證 + 角色權限，取代現有的無密碼身份選擇機制
11. 個人班表/個案總覽：僅顯示登入者自己被排的時段與個案
12. 諮商紀錄輸入：拍照上傳手寫紙本 或 線上直接打字，兩種方式並存，可回顧自己過去的紀錄
13. 抽成透明化查詢：心理師可查詢自己當月/當次算出的抽成金額

**管理報表**
14. 營收總覽：當月/當季收入、依方案佔比、應收未收一覽
15. 抽成結算報表：依規則自動算出每位心理師應領金額，可匯出（不含扣繳稅額/二代健保補充保費計算，見「不涵蓋」）
16. 心理師產能總覽：個案量、時段滿載度
17. 方案成效總覽：進案量、完成率、流失率

**合規機制**
18. 存取稽核紀錄：記錄誰在何時查看/修改/匯出/刪除過哪筆個案紀錄
19. 當事人資料更正/刪除機制：支援個案依個資法規定要求更正或刪除自己資料的操作流程；刪除動作需考慮與「業務紀錄至少保存十年」的法定義務之間的衝突（見「法規依據」），不可做成無條件硬刪除

### 不涵蓋（V1 刻意排除）

- **心理師可用時段自助更新**：V1 先由行政手動維護心理師可服務時段，心理師本人自助調整留給後續版本
- **抽成稅務代扣計算（扣繳稅額、二代健保補充保費）**：是否需要系統計算、或維持現狀交由診所會計師另行處理，待確認，見「待確認事項」
- **多租戶 SaaS 架構**：見下方「架構決策」，刻意不做

## 架構決策

### 單租戶、自架部署，不做多租戶 SaaS

V1 延續信件模板系統時期已驗證的方向（`docs/NAS_SETUP.md`）：每個部署單位服務一家診所，資料庫與執行環境彼此獨立，不共用。不做跨組織的多租戶資料隔離、租戶管理後台、計費系統——這些是完全不同量級的工程，且與「資料留在自己機器上、不跟其他使用者共享資料庫」的定位相符。

### 身份驗證從無到有

**這是對現有設計原則的實質變更**：CLAUDE.md 目前記載「No password, ever — by design」，前提是操作者皆為同一台機器前的少數行政人員。心理師自助功能一旦存在，前提不再成立——使用者數從 5 人增至約 35 人、彼此不相識、且需要跨裝置/跨網路連線、系統開始存放真實諮商紀錄內容。因此 V1 必須新增：

- 密碼驗證（或等效機制）取代現有的「從名單點選」
- 角色權限系統（至少三層：一般行政 / 心理師 / 財務管理者——財務資料獨立權限層級，理由見下）
- HTTPS（心理師可能從診所外連線，不能再假設僅限內網 plaintext）

此變更待實作階段再動現有程式碼，本文件僅記錄決策與理由。

### 財務資料獨立權限層級

營收、抽成金額等財務資料，建議設計成獨立於「一般行政 vs 心理師」之外的第三層權限——一般行政可操作排程/出席，但不必然能看到金額明細；僅財務管理者（可能是主管本人或特定授權人員）能看完整金額報表。

## 資料模型草案

以下為概念層級欄位草案，供後續 `writing-plans` 階段轉換成實際 Prisma schema，非最終定案：

- **Plan（方案）**：名稱、預設收費、時長、抽成規則（公式類型 + 參數）、是否停用
- **Case（個案）**：姓名、所屬方案、指派心理師、狀態（待排/治療中/已結案）、建檔時間——實際完整欄位清單待主管確認（見「待確認事項」）
- **Schedule（排程）**：所屬個案、心理師、場地、起訖時間、週期規則（選填）
- **Attendance（出席）**：對應排程、狀態（已到/未到/請假/改期）、回報者（行政或心理師）、若為改期則連結新排程記錄
- **Payment（收款）**：對應個案/場次、金額、收款狀態、收款方式、收據編號、作廢/修改歷程
- **TherapistProfile（心理師資料擴充）**：可服務時段（每週樣板）、擅長方案（關聯 Plan）、預設抽成比例
- **User（使用者，含既有 users 表擴充）**：角色（一般行政/心理師/財務管理者）、密碼雜湊——取代現有無密碼設計
- **Record（諮商紀錄）**：對應個案、心理師、內容（文字或附件參照）、建立時間、保存期限標記（配合心理師法十年保存義務，不可無條件硬刪除）
- **AuditLog（存取稽核）**：操作者、動作類型（查看/修改/匯出/刪除）、對象實體與 ID、時間

## 法規依據

- **心理師法**：執行業務之紀錄應妥為保管，**至少保存十年**——直接影響 Record 的保存/刪除機制設計，不可做成可任意永久刪除。
- **個資法**：要求「適當之安全維護措施」——資料敏感度自本次規劃起大幅提升（真實諮商紀錄內容），加密、存取控制、備份規格需對應提升，不可再沿用信件模板系統時期「反正沒存真資料」的寬鬆標準；同時賦予當事人查閱/更正/刪除個資的權利，對應功能範圍第 19 項。

## 待確認事項（需要主管或外部專業確認，不是技術問題）

1. **個案實際建檔欄位清單**：需要主管提供實際要蒐集的欄位，無法由技術規劃代為假設。
2. **值班儀表板提醒規則的彈性程度**：「可自訂規則引擎」與「固定寫死幾種提醒」工時差距約 2–3 倍，需要主管依預算決定。
3. **個案換心理師、或同一人參與多個方案（平行/先後）時的資料處理邏輯**：無強烈業界慣例可循，需依診所實務決定。
4. **抽成稅務代扣（扣繳稅額、二代健保補充保費）是否需要系統計算**：需診所會計師確認現行處理方式。
